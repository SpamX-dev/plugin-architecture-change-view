# Форматы arch.yaml и review.yaml — v1

Действующая схема контрактов и результатов проверки. arch.yaml — единственный
формат ответственности каталога; module.md подлежит немедленному переносу.
Если обоих файлов нет, агент анализирует исходники и границы предков и записывает
arch.yaml до продолжения работы или просмотра выбранного дерева.

## Модель документов

- **arch.yaml** — согласованный контракт модуля рядом с исходниками.
- **Снимок** — сохранённые факты о коде, структуре и контрактах.
- **review.yaml** — неизменяемый результат анализа одного модуля для выбранной
  пары снимков. Хранится в каталоге результатов анализа отдельно от исходников.

Собственный arch.yaml предусмотрен в каждом каталоге дерева исходников,
включая вложенные каталоги, тесты, скрипты и общие каталоги дерева.
Зависимости и результаты генерации или сборки исключаются.
Контракт предка не заменяет локальное описание.

arch.yaml заменяет module.md как источник ответственности.
Одинаковые обязанности не поддерживаются одновременно в двух форматах.
ArchiView отображает структурированный контракт как документ.

Ниже приведён полный состав полей v1. Обязательные коллекции могут быть пустыми
только там, где это явно разрешено.

## arch.yaml

### Поля

| Поле | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| schema_version | Да | Целое | Версия формата, сейчас 1 |
| id | Да | Строка | Устойчивый идентификатор модуля, уникальный в проекте |
| title | Да | Строка | Человекочитаемое название |
| kind | Да | Перечисление | module — модуль с собственной ответственностью; group — каталог, объединяющий модули |
| purpose | Да | Строка | Для чего существует модуль, за какой результат отвечает |
| responsibilities | Да | Словарь строк | Обязанности: идентификатор пункта → описание. Минимум один пункт |
| boundaries | Да | Словарь строк | Что находится за пределами ответственности. Допустимо {} |
| invariants | Да | Словарь строк | Устойчивые условия, сохраняемые при изменениях. Допустимо {} |
| rationale | Нет | Строка | Почему выбраны такие границы |
| owners | Нет | Массив строк | Ответственные команды или устойчивые идентификаторы владельцев |
| tags | Нет | Массив строк | Метки для поиска и группировки |
| references | Нет | Массив ссылок | Связанные архитектурные решения и документы |
| extensions | Нет | Словарь | Расширения с именами вида organization.field |

Элемент references содержит два обязательных строковых поля: title и uri.
URI может быть внешней ссылкой или путём относительно корня репозитория.

### Пример

```yaml
schema_version: 1

id: archiview-http
title: HTTP-интерфейс ArchiView
kind: module

purpose: >
  Предоставлять локальному интерфейсу данные
  для просмотра архитектурных изменений.

responsibilities:
  R1: Предоставлять дерево модулей выбранного сравнения.
  R2: Предоставлять документы и результаты проверки модуля.
  R3: Принимать запросы пользователя на сохранение снимка.

boundaries:
  B1: Формирование снимков принадлежит общей модели.
  B2: Отрисовка документов принадлежит клиентскому интерфейсу.

invariants:
  I1: Исходники анализируемого проекта не изменяются.
  I2: Дерево и документы относятся к одной паре снимков.
  I3: HTTP-интерфейс доступен только локально.

references:
  - title: Архитектура приложения
    uri: docs/architecture.md
```

Пример иллюстрирует формат и не является результатом миграции действующего
контракта HTTP-модуля.

### Идентичность и наследование

- id сохраняется при перемещении и переименовании каталога.
- Идентификаторы пунктов сохраняются при уточнении формулировки. Идентификатор
  удалённого пункта не используется повторно для другого требования.
- Путь определяется расположением файла. Поля path и parent не нужны.
- Родительские границы и инварианты действуют на поддерево. Родительские
  обязанности задают контекст, но не становятся целиком обязанностями каждого
  потомка.
- Для group описывается собственная роль объединения и распределения
  ответственности. Не требуется придумывать независимое поведение для каждого
  промежуточного каталога.
- Статусы реализации, результаты проверок, даты и перечень текущих файлов
  относятся к другим данным.
- Изменение реализации само по себе не разрешает расширять контракт.
  Изменение границ согласуется с пользователем; явного разрешения в текущей
  задаче достаточно, повторное согласование не требуется.

## review.yaml

### Поля верхнего уровня

| Поле | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| schema_version | Да | Целое | Версия формата, сейчас 1 |
| id | Да | Строка | Уникальный идентификатор отчёта |
| module | Да | Объект | Идентичность модуля и его расположение в обоих снимках |
| comparison | Да | Объект | Точные ссылки на сравниваемые снимки |
| analysis | Да | Объект | Анализатор, параметры, область и полнота проверки |
| observed | Да | Объект | Ответственность, выведенная из кода каждой стороны |
| checks | Да | Массив | Результаты проверки конкретных пунктов контрактов |
| findings | Да | Массив | Обнаруженные проблемы и изменения, требующие внимания |
| assessment | Да | Объект | Итоговая оценка состояния и изменения |
| references | Нет | Массив ссылок | Связанные отчёты и документы; формат как в arch.yaml |
| extensions | Нет | Словарь | Расширения с пространством имён |

checks: [] и findings: [] допустимы, но сами по себе не означают успешную
проверку: результат зависит от полноты анализа и итоговой оценки.

### module: идентичность

| Поле | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| id | Да | Строка или null | Идентификатор из контракта. null, если контракт отсутствует и идентичность неизвестна |
| baseline_path | Да | Строка или null | Каталог в базовом снимке |
| current_path | Да | Строка или null | Каталог в текущем снимке |

Хотя бы один путь должен присутствовать. Пути задаются относительно корня
проекта, с /; корень обозначается ".".

### comparison: снимки

| Поле | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| baseline | Да | Ссылка на снимок или null | Базовый снимок; null для первого анализа |
| current | Да | Ссылка на снимок | Текущий снимок проекта |

Каждая ссылка содержит обязательные строковые поля id и digest.

Даже при удалении модуля comparison.current существует: это снимок проекта,
в котором модуль уже отсутствует.

### analysis: описание анализа

| Поле | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| created_at | Да | Строка | Время создания в UTC |
| analyzer | Да | Объект | name, version, config_digest — все обязательны и имеют тип строка |
| input_digest | Да | Строка | Отпечаток полного набора входов анализа |
| scope | Да | Перечисление | module — модуль целиком; changes — изменения и необходимый контекст |
| coverage | Да | Объект | Полнота проверки |
| model | При использовании ИИ | Объект | Обязательные строки provider, id; необязательные строка revision и словарь parameters |
| prompt_digest | При использовании ИИ | Строка | Отпечаток применённых инструкций |

Объект coverage содержит два обязательных поля:

```yaml
coverage:
  status: complete
  limitations: []
```

- status: complete, partial или unavailable.
- limitations: массив строк с конкретными ограничениями, например:
  неподдерживаемый язык, неразрешённые вызовы, недоступные файлы.

complete означает полноту выбранной области проверки, а не доказанное
отсутствие любых архитектурных проблем.

input_digest учитывает снимки, эффективные контракты, настройки, инструкции
и дополнительный контекст, использованный анализатором. Манифест этих входов
сохраняется вместе с результатом.

### observed: выведенная ответственность

Объект observed содержит обязательные baseline и current. Каждая сторона —
объект следующего вида либо null, если модуль на этой стороне отсутствует:

```yaml
summary: Предоставляет HTTP-доступ к данным сравнения.

responsibilities:
  - text: Возвращает дерево модулей выбранного снимка.
    evidence:
      - snapshot: current
        fact_id: fact-42
```

Обязательные поля стороны:

- summary — строка с обобщённым описанием наблюдаемой роли.
- responsibilities — массив выведенных обязанностей.
- У каждой обязанности обязательны строка text и непустой массив evidence.

Если модуль существует, но данных недостаточно, сохраняется объект с пустым
массивом обязанностей и соответствующим ограничением в coverage. Отсутствие
контракта не мешает отдельно описать наблюдаемое поведение.

### checks: проверка пунктов контракта

| Поле элемента | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| id | Да | Строка | Уникальный идентификатор проверки внутри отчёта |
| contract | Да | Ссылка на пункт | Точная ссылка на проверяемый пункт контракта |
| subject | Да | Перечисление | Какой код проверяется: baseline или current |
| verdict | Да | Перечисление | Результат проверки |
| explanation | Да | Строка | Обоснование результата |
| evidence | Да | Массив ссылок на доказательства | Данные, на которых основан результат |

Ссылка contract содержит четыре обязательных строковых поля:

```yaml
contract:
  snapshot: baseline
  module_id: archiview-http
  section: boundaries
  id: B1
```

- snapshot: baseline или current.
- module_id: идентификатор модуля, которому принадлежит пункт.
- section: responsibilities, boundaries или invariants.
- id: идентификатор пункта внутри раздела.

Значения verdict:

| Значение | Смысл |
| --- | --- |
| consistent | Рассмотренные данные согласуются с пунктом |
| violation | Обнаружено противоречие пункту |
| uncertain | Данные допускают разные трактовки |
| not_checked | Проверка не выполнена; причина обязательна в объяснении |
| not_applicable | Пункт неприменим к рассматриваемому состоянию |

Для consistent и violation нужны доказательства. Для остальных результатов
массив может быть пустым.

Контракт и проверяемый код могут относиться к разным снимкам. Это позволяет
проверять:

- прежний код по прежнему контракту;
- текущий код по текущему контракту;
- текущий код по прежнему контракту.

Последняя проверка нужна, чтобы одновременное изменение кода и расширение
arch.yaml оставалось видимым.

В отчёте должна быть запись для каждого проверяемого локального пункта и
применимого родительского ограничения. Пропущенная проверка обозначается
явно через not_checked.

### findings: замечания

| Поле элемента | Обязательное | Тип | Значение |
| --- | --- | --- | --- |
| id | Да | Строка | Идентификатор замечания внутри отчёта |
| kind | Да | Перечисление | Категория замечания |
| certainty | Да | Перечисление | confirmed или suspected |
| severity | Да | Перечисление | info, warning или error |
| lifecycle | Да | Перечисление | introduced, persisting, resolved или unknown |
| summary | Да | Строка | Суть замечания и его причина |
| clauses | Да | Массив ссылок на пункты | Точные ссылки на пункты контрактов |
| evidence | Да | Массив ссылок на доказательства | Непустой массив доказательств |
| details | Нет | Строка | Развёрнутое объяснение |
| recommendation | Нет | Строка | Предлагаемое действие |
| related_modules | Нет | Массив строк | Идентификаторы затронутых модулей |

Состав kind для v1:

| Значение | Смысл |
| --- | --- |
| boundary_violation | Выход за установленную границу |
| invariant_violation | Нарушение устойчивого ограничения |
| undeclared_responsibility | Наблюдаемая обязанность не отражена в контракте |
| responsibility_gap | Обнаружен разрыв в выполнении заявленной обязанности |
| contract_conflict | Противоречие между контрактами |
| contract_change | Существенное изменение самого контракта |
| missing_contract | Отсутствует необходимый arch.yaml |

clauses может быть пустым, например при отсутствии контракта. Формат ссылки
совпадает с checks[].contract.

Различия при интерпретации:

- Неописанная обязанность не обязательно запрещена.
- Отсутствующая реализация не обязательно нарушает контракт: он может
  описывать согласованный будущий модуль.
- resolved требует подтверждения устранения проблемы. Удаление ограничения
  из контракта само по себе не означает исправление.
- severity описывает последствия, а certainty — обоснованность вывода.

### Ссылки на доказательства

Везде используется одинаковая ссылка:

```yaml
snapshot: current
fact_id: fact-42
```

Оба поля обязательны и имеют тип строка. snapshot принимает baseline или
current; fact_id разрешается внутри указанного сохранённого снимка.

Сам факт должен содержать происхождение: файл, символ или пункт контракта,
необходимые координаты и зафиксированное содержимое либо доступную
историческую версию. Один хеш изменяемого файла недостаточен для просмотра
доказательства.

### assessment: итоговая оценка

Объект assessment содержит два обязательных результата:

```yaml
assessment:
  current:
    verdict: consistent
    summary: Текущий код соответствует текущему контракту.

  change:
    verdict: needs_review
    summary: Контракт расширен одновременно с добавлением новой обязанности.
```

У каждого результата обязательны строковые поля verdict и summary.

Общий набор значений verdict:

| Значение | Смысл |
| --- | --- |
| consistent | Рассмотренные данные согласуются с контрактом |
| violation | Обнаружено нарушение |
| needs_review | Требуется решение по выявленному изменению или неоднозначности |
| inconclusive | Данных недостаточно для вывода |
| not_applicable | Оценка неприменима |

current оценивает текущее состояние по текущему контракту. change оценивает
изменение относительно зафиксированной ответственности базового снимка.

Для первого анализа change будет not_applicable. Для удалённого модуля
current может быть not_applicable, но последствия удаления всё равно
оцениваются в change.

## Общие правила формата и хранения

1. Неизвестные поля считаются ошибкой. Дополнительные данные размещаются
   в extensions; изменение стандартной схемы требует новой версии.
2. Дублирующиеся YAML-ключи запрещены. Используются обычные строки, числа,
   логические значения, массивы и словари.
3. Необязательное поле пропускается. null используется только в явно
   описанных случаях.
4. Отпечатки записываются как sha256:<hex>. Правила их вычисления едины
   для всех компонентов.
5. Отчёт не изменяется после сохранения. Повторный анализ создаёт новый
   review.yaml.
6. Устаревание отчёта вычисляется по его входам. Поле stale в сам файл
   не записывается.
7. Статусы дерева new, changed, removed, unchanged вычисляются из снимков
   отдельно от оценки соответствия. Без базового снимка используется initial.
8. Сравнение с предыдущим индексом и сравнение с принятым checkpoint создают
   отдельные отчёты — так непосредственное изменение и накопленное отклонение
   остаются различимыми.

## Подготовка и поддержка

module_inventory возвращает preparation: ready, migrate, analyze_and_write или repair.
module.md не считается покрытием: агент сразу переносит содержание в arch.yaml,
проверяет YAML и удаляет старый файл. Если есть оба файла, агент сначала сверяет
ограничения. Если нет обоих — анализирует код и контекст предков и пишет контракт.
Инструменты MCP и браузерный просмотр читают проект; анализ и запись выполняет
агент согласно каноническому скиллу. Они не запускают скрытый ИИ-процесс.

Встроенный анализатор archiview-structure проверяет наличие и изменение контрактов.
Он создаёт review.yaml с coverage: partial, наблюдаемым количеством исходников и
явными not_checked для всех локальных пунктов и наследуемых ограничений, в том
числе проверкой текущего кода по базовому контракту. Он не выводит обязанности из
кода и не подтверждает семантическое соответствие. Внешний анализатор может
предоставить полный отчёт с доказательствами в том же формате.

## Снимки и пакет результата

Снимок v2 содержит modules, сохранённые facts, evidenceLimitations и digest.
Факт имеет id, kind (file или module), path, text; файловый факт также хранит
start_line и end_line. id факта — SHA-256 его канонического содержимого без id.
Текст нормализуется к LF. Один контракт ограничен 128 KiB, исходный файл —
256 KiB; суммарный бюджет текстов — 16 MiB. Ограничение доказательств сообщается
отдельно от полноты обхода. Отсутствующий факт нельзя использовать в отчёте.
Исторические снимки v1 доступны для сравнения, но не выдают хеш за доказательство.

digest снимка вычисляется из root, modules, facts, complete, diagnostics и
evidenceLimitations. Время, id и пользовательская метка в него не входят.
Объекты сериализуются в JSON с лексикографически отсортированными ключами,
порядок массивов сохраняется, кодировка UTF-8. undefined в объектах пропускается.
Формат всех внешних отпечатков — sha256:<64 lowercase hex>.

Каждый результат хранится отдельной неизменяемой папкой вне исходников:

~~~text
reviews/review-<sha256 от id отчёта>/
  review.yaml
  input.json
  current.json
  baseline.json  # только если есть база
~~~

input.json содержит schema_version: 1, comparison, module, analyzer, scope,
contracts (baseline/current — массивы {reference, text} эффективных пунктов),
instructions и context. Для ИИ также model и prompt_digest, совпадающие с отчётом.
Дополнительные входы помещаются в context. analysis.input_digest — SHA-256 всего
канонического input.json. Все используемые инструкции и контекст сохраняются;
ссылки на изменяемые внешние файлы без зафиксированного содержания недостаточны.

Импорт проверяет схему, идентичность модуля, хеши снимков и входов, каждый пункт и
факт, а также явное присутствие проверки применимых ограничений. Повторная запись
того же id запрещена. Устаревание вычисляется по содержимому обоих снимков; для
встроенного анализатора также учитываются версия и настройки. Произвольный
внешний контекст считается зафиксированным в манифесте, а не отслеживаемым ресурсом.
