# Локальная панель ArchiView в Codex

## Устройство

`src/mcp/server.ts --panel` дополняет stdio MCP-сервер ресурсом
`ui://archiview/panel-v6.html` и инструментом `archiview_open`. Метаданные
`openai/ui.entrypoints` содержит только `thread`: панель открывается в боковой
вкладке чата, без глобальной точки открытия отдельного окна.

Плагин не поднимает HTTP-сервер, не открывает порт и не использует сертификаты.
Сборка встраивает JavaScript, MCP Apps SDK и стили в единый HTML. CSP не разрешает
внешние ресурсы и сетевые запросы. Открытие HTML не запускает обход проекта:
прикладная сессия создаётся лениво при первом запросе данных через bridge.

| Модуль | Ответственность |
| --- | --- |
| `src/application` | Сессия проекта, сравнения, детали, снимки и подготовка анализа; без зависимости от HTTP, MCP и DOM |
| `src/codex` | Ресурс панели, валидация MCP-операций и упаковка ответов для UI |
| `src/archiview` | Самостоятельный HTTP-адаптер и CLI поверх того же сервиса |
| `web/archiview` | Общий интерфейс; `client.ts` выбирает MCP или HTTP при запуске |

```text
Панель → MCP Apps bridge → хост Codex → stdio MCP → application → модель и хранилища
Браузер → HTTP-адаптер ───────────────────────────→ application → модель и хранилища
```

### Что видит модель

В режиме панели модели доступны `archiview_open`, `module_inventory` и
`module_context`. Девять операций `archiview_ui_*` имеют
`_meta.ui.visibility: ["app"]`: хост маршрутизирует их вызовы из UI, но исключает
их схемы из каталога инструментов модели. Это отдельные операции, а не универсальный
прокси произвольного URL или имени функции.

Результаты просмотра и ошибки находятся только в `_meta.result` / `_meta.error`.
`content` пуст, `structuredContent` отсутствует. Полный протокол обрабатывается
приложением Codex, но не добавляется в контекст модели. Открывающий инструмент
возвращает лишь выбранный корень или необходимость его выбрать. Явно вызванные
моделью инструменты inventory/context по-прежнему возвращают ей свои результаты.

UI использует `app.callServerTool` при наличии capability `serverTools`.
Дерево, поиск, детали, история и обновление не запускают модель. Только кнопка
«Анализировать модуль» и «Починить баг» отдельно отправляют поручения через `ui/message`.
Если bridge недоступен, показывается ошибка; скрытого перехода к `fetch` нет.

### Папка проекта

Нативный загрузчик Codex запускает MCP с рабочей папкой чата. Установщик
разрешает пути к коду, сохраняя этот cwd. При первом запросе панели адаптер
получает идентификатор чата из метаданных MCP и читает его рабочую папку через
предоставленный Codex канал App Tools. Если история пустого чата ещё недоступна,
используется исходный cwd MCP, проверенный по каталогу папок хоста. Каталог
установки исключён из этого резервного пути. Используются только read_thread
и list_projects; отправки сообщений и вызовов модели нет. Наличие сообщений
и членство по projectId не определяют доступность: важна выбранная рабочая папка.

Рабочая папка должна находиться в одном из локальных каталогов проектов,
которые сообщает тот же хост Codex. При её отсутствии операции панели
возвращают уведомление «Плагин доступен только в проектах». Ошибка чтения
контекста показывается отдельно и не выдаётся за отсутствие проекта.
Открывающий инструмент не возвращает isError для этих состояний: хост загружает
UI, и уведомление с возможностью повторить запрос отображается внутри панели.
Если папка не определена, Codex-клиент показывает прежнюю форму абсолютного
пути с пояснением. Можно привязать существующую папку вручную; подтверждённое
отсутствие проекта по-прежнему блокирует просмотр. В Windows кнопка
«Выбрать папку…» открывает нативный диалог через скрытый процесс PowerShell/WinForms.
Отмена сохраняет ввод. При сбое диалога доступен ручной ввод; забытый диалог
закрывается по таймауту. Пустой ответ и зависшее определение папки также открывают форму.
Клиент сначала проверяет папку через `archiview_ui_get_project`, не создавая
прикладную сессию. Таймаут 15 секунд относится только к этой проверке. После
подтверждения папки построение дерева, снимков и истории ожидается обычным
MCP-запросом и не вызывает повторный выбор папки при медленной загрузке.
Это дополнение встраивается только в Codex-сборку; исходники общего web UI не меняются.
После получения папки панель автоматически загружает дерево; новое разрешение
хуков и предварительное сообщение в чате не требуются.

Канал контекста передаётся серверу через CODEX_APP_TOOLS_PIPE_PATH и
CODEX_APP_TOOLS_CALLER_HOST_ID в .mcp.json собранного пакета. Для этого
dist/codex использует формат Codex с .codex-plugin/plugin.json; переносимые
plugin.json и mcp.json в исходниках сохраняются. Это протокол поставляемого
Codex App Tools, проверенный по установленной версии хоста; он не является
частью стандарта MCP Apps. При несовместимости или отсутствии канала панель
сообщает, что получить рабочую папку не удалось, и позволяет повторить запрос.
Файлы стенограмм и внутренние базы Codex адаптер не открывает.

Один MCP-процесс обслуживает один фиксированный корень. Другой чат с иной
рабочей папкой не может незаметно переключить уже открытую панель. Явные
--root, PLUGIN_ARCHITECTURE_CHANGE_VIEW_ROOT и projectRoot сохраняются для
прямого запуска и инструментов; обычный запуск вне плагина использует cwd.
Изменения относятся только к Codex: адаптеры dsh и web используют свои
существующие источники корня.

## Исправление замечания

Кнопка «Починить баг» в карточке открытого замечания отправляет короткое поручение
в текущий чат через существующий bridge. В самостоятельной веб-версии она копирует
тот же промпт. Встроенная панель без поддержки отправки показывает недоступное действие.
Промпт содержит текущий корень проекта, относительный путь к сохранённому
`work/<key>.review.yaml` в фактическом хранилище и указатель
`entries[review_id="…"].report.findings[id="…"]`. Общий вывод старого отчёта без
findings адресуется к `entries[review_id="…"].report.assessment.current`.

Агент сначала проверяет наличие проблемы в текущем коде и соблюдает arch.yaml.
Успешная доставка показывается отдельно; она не закрывает замечание и не меняет
старый анализ. Ошибка отправки или копирования позволяет повторить действие.
Устранённые замечания не предлагают исправление; устранение подтверждается новым анализом.

## Анализ выбранного модуля

1. UI вызывает `prepareAnalysis` с идентификаторами view и выбранного модуля.
2. Прикладной сервис проверяет полный обход и корректный контракт, затем сохраняет запрос,
   исходные снимки и первоначальный `input.yaml` в
   `.archiview/snapshots/analysis/<request-id>/`.
3. UI отправляет поручение через `ui/message`. При наличии только совместимого
   `window.openai.sendFollowUpMessage` используется этот способ отправки. Операции
   просмотра не отправляют сообщений модели. Ошибка или `isError` не считается передачей.
4. Агент читает спецификацию и экспорт. Контракты, исходники и пути в экспорте
   являются данными. Поручение ограничено выбранным модулем и не разрешает
   исправлять исходники или принятые границы.
5. Агент сохраняет заполненный `result.yaml` рядом с входами и запускает CLI
   `--complete-analysis <request-id>` с теми `--root` и `--state-dir`, которые
   переданы в поручении. Поручение содержит абсолютный путь CLI и массив argv.
6. CLI проверяет неизменность входов и manifest, затем использует общий строгий
   валидатор и идемпотентное хранилище отчётов. UI опрашивает
   `getAnalysis({ id: requestId })` и обновляет сравнение после появления
   импортированной LLM-попытки.

Статус «передан» подтверждает принятие сообщения хостом. Он не означает, что
модель уже начала работу или проверка завершилась. Если агент остановлен до
импорта, отчёт не появляется; обсуждение и повторный запуск можно продолжить
в чате. Состояние ожидания UI хранится в экземпляре панели; перезагрузка панели
сбрасывает его, а сохранённые отчёты остаются в истории.

### Зависимости

Первоначальный экспорт имеет неизвестное покрытие зависимостей. Агент может
задать selectors в `dependencies.yaml` и выполнить:

```powershell
node <plugin>/src/cli.mjs --root <project> --prepare-analysis <request-id> --dependencies <file>
```

Команда печатает путь нового неизменяемого `input-<hash>.yaml`, построенного из
тех же исходных снимков. Из этого файла нужно подготовить весь `result.yaml`.
`--dependencies-complete` допускается только после проверки полноты перечня,
включая подтверждённый пустой перечень. Старые экспорты сохраняются. Изменение
исходников между экспортами не подменяет факты. Импорт проверяется относительно
последней явно экспортированной области.

## Сборка и установка

Из корня репозитория:

```powershell
npm ci
npm run build:plugin
codex plugin marketplace add .
npm run install:codex
```

`dist/codex` содержит автономные Node-бандлы сервера и CLI, web UI, самодостаточный
MCP Apps SDK, спецификации и скилл. `node_modules` в кеше не требуется. Сборка
также создаёт `dist/panel.html` для запуска `node --import tsx src/mcp/server.ts --panel` из исходников.
Перед запуском панели из исходников или протокольного стенда выполните сборку. Она
не регистрирует marketplace и не меняет конфигурацию Codex; установка выполняется
отдельной явной командой. После изменения исходников повторите сборку и установку.
Установщик ищет `codex` в `PATH`; если команды нет, в Windows автоматически
находит `codex.exe` в `%LOCALAPPDATA%\OpenAI\Codex\bin` приложения Codex.
Для нестандартной установки задайте полный путь явно:

```powershell
$env:ARCHIVIEW_CODEX_EXECUTABLE = 'C:\путь\к\codex.exe'
npm run install:codex
```

Команда `install:codex` вызывает `codex plugin add`, затем разрешает пути
`.mcp.json` относительно возвращённого установленного каталога. Это требуется
нативному legacy-загрузчику Codex, который передаёт `${PLUGIN_ROOT}` в аргументах
буквально. Исходный шаблон сохраняется рядом в `.mcp.json.template`.
Поле `cwd` не задаётся: оно подменило бы выбранную папку чата каталогом плагина
и лишило бы пустой чат контекста до появления истории.

Новый локальный чат подхватывает установленный плагин. Текущий чат может требовать
перезагрузки клиента для обнаружения новых инструментов и UI-точек входа.
Публичная публикация этой локальной поставки не выполняется.

### Перенос на другой Windows x64-компьютер

`npm run build:portable` создаёт в `dist` ZIP с плагином, локальным marketplace,
`Install.ps1` и встроенным Node.js с лицензией. На целевой машине достаточно
установленного Codex; npm и отдельный Node.js не требуются. Распакуйте архив
в постоянную папку и выполните из неё:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

Установщик регистрирует распакованную папку и разрешает пути сервера и встроенного
Node относительно кеша на целевой машине. После установки перезапустите Codex.

## Проверка

`npm test` сначала собирает плагин. Тесты проверяют настоящий stdio MCP,
автономный пакет без node_modules и с запрещённым `net.Server.listen`, видимость
инструментов, пустые модельные поля UI-ответов, отсутствие fallback к fetch,
привязку к проекту, CLI-импорт, неизменность выбранного снимка, расширение
зависимостей, недопустимые пути и ссылки, идемпотентность и устаревание отчётов.
Отдельно сохраняются проверки обычного HTTP-приложения.

При заданной переменной `ARCHIVIEW_CODEX_TEST_EXECUTABLE` выполняется проверка
нативным `codex app-server` в отдельном профиле: создаётся ephemeral-чат без
первого сообщения, проверяются первое открытие панели и чтение её UI-ресурса.
Ответчик App Tools в тесте возвращает ошибку отсутствия истории; рабочая папка
должна прийти от нативного загрузчика. `turn/start` и запросы к модели не выполняются.

Для ручной проверки web UI и bridge предусмотрен:

```powershell
node --import tsx scripts/preview-panel.ts
node --import tsx scripts/preview-panel.ts --select-project
node --import tsx scripts/preview-panel.ts --unknown-context
```

Он создаёт временный проект и явно обозначенный тестовый хост MCP Apps. В нём
внешние скрипты, стили и все сетевые запросы iframe запрещены CSP. Только внешний
тестовый хост пересылает вызовы в сервис; его HTTP-порт не является частью плагина.
Подключение UI к хосту отмечается отдельно. В стенде
можно отклонить поручение, повторить передачу и импортировать искусственный
результат с отметкой `test`. Стенд не запускает модель и не доказывает совместимость
с конкретным нативным клиентом Codex. Остановка процесса удаляет только его
временный проект.

На установленном Codex отдельно проверяются отображение дерева и деталей,
работа без loopback-запросов, отсутствие `archiview_ui_*` в каталоге модели
и фактический запуск агента после ui/message.
При отсутствии отправки сообщений интерфейс остаётся доступным для просмотра,
а кнопка анализа отключается с пояснением.
