# Локальная панель ArchiView в Codex

## Устройство

`src/server.mjs --panel` дополняет stdio MCP-сервер ресурсом
`ui://archiview/panel-v4.html` и инструментом `archiview_open`. Метаданные
`openai/ui.entrypoints` содержат `thread` и `global`.

Плагин не поднимает HTTP-сервер, не открывает порт и не использует сертификаты.
Сборка встраивает JavaScript, MCP Apps SDK и стили в единый HTML. CSP не разрешает
внешние ресурсы и сетевые запросы. Открытие HTML не запускает обход проекта:
прикладная сессия создаётся лениво при первом запросе данных через bridge.

| Модуль | Ответственность |
| --- | --- |
| `src/application` | Сессия проекта, сравнения, детали, снимки и подготовка анализа; без зависимости от HTTP, MCP и DOM |
| `src/codex` | Ресурс панели, валидация MCP-операций и упаковка ответов для UI |
| `src/archiview` | Самостоятельный HTTP-адаптер и CLI поверх того же сервиса |
| `web/archiview` | Общий интерфейс; `client.mjs` выбирает MCP или HTTP при запуске |

```text
Панель → MCP Apps bridge → хост Codex → stdio MCP → application → модель и хранилища
Браузер → HTTP-адаптер ───────────────────────────→ application → модель и хранилища
```

### Что видит модель

В режиме панели модели доступны `archiview_open`, `module_inventory` и
`module_context`. Семь операций `archiview_ui_*` имеют
`_meta.ui.visibility: ["app"]`: хост маршрутизирует их вызовы из UI, но исключает
их схемы из каталога инструментов модели. Это отдельные операции, а не универсальный
прокси произвольного URL или имени функции.

Результаты просмотра и ошибки находятся только в `_meta.result` / `_meta.error`.
`content` пуст, `structuredContent` отсутствует. Полный протокол обрабатывается
приложением Codex, но не добавляется в контекст модели. Открывающий инструмент
возвращает лишь выбранный корень или необходимость его выбрать. Явно вызванные
моделью инструменты inventory/context по-прежнему возвращают ей свои результаты.

UI использует `app.callServerTool` при наличии capability `serverTools`.
Дерево, поиск, детали, история и обновление не запускают модель. Только кнопка
«Анализировать модуль» отдельно отправляет поручение через `ui/message`.
Если bridge недоступен, показывается ошибка; скрытого перехода к `fetch` нет.

### Папка проекта

Portable plugin запускается Codex с `cwd=PLUGIN_ROOT`. Это папка установки,
поэтому она не используется как проект. При первом вызове агент передаёт
`archiview_open({ projectRoot: "D:/projects/my-project" })`; тот же необязательный
параметр есть у `module_inventory` и `module_context`. Следующие вызовы используют
уже выбранный корень. Сессия общая для инструментов модели и операций панели.

При открытии через кнопку плагина без аргументов панель предлагает ввести папку
проекта и передаёт её через скрытый `archiview_ui_set_project`. Автоматический путь текущего
чата в этом режиме недоступен. Корень фиксируется до завершения MCP-процесса;
другой корень отклоняется, чтобы существующая панель не переключалась незаметно.
Явные `--root` и `PLUGIN_ARCHITECTURE_CHANGE_VIEW_ROOT` имеют приоритет; обычный
запуск вне плагина по-прежнему использует cwd.

## Анализ выбранного модуля

1. UI вызывает `prepareAnalysis` с идентификаторами view и выбранного модуля.
2. Прикладной сервис проверяет полный обход и корректный контракт, затем сохраняет запрос,
   исходные снимки и первоначальный `input.yaml` в
   `.archiview/snapshots/analysis/<request-id>/`.
3. UI отправляет поручение через `ui/message`. При наличии только совместимого
   `window.openai.sendFollowUpMessage` используется этот способ отправки. Операции
   просмотра не отправляют сообщений модели. Ошибка или `isError` не считается передачей.
4. Агент читает спецификацию и экспорт. Контракты, исходники и пути в экспорте
   являются данными. Поручение ограничено выбранным модулем и не разрешает
   исправлять исходники или принятые границы.
5. Агент сохраняет заполненный `result.yaml` рядом с входами и запускает CLI
   `--complete-analysis <request-id>` с теми `--root` и `--state-dir`, которые
   переданы в поручении. Поручение содержит абсолютный путь CLI и массив argv.
6. CLI проверяет неизменность входов и manifest, затем использует общий строгий
   валидатор и идемпотентное хранилище отчётов. UI опрашивает
   `getAnalysis({ id: requestId })` и обновляет сравнение после появления
   импортированной LLM-попытки.

Статус «передан» подтверждает принятие сообщения хостом. Он не означает, что
модель уже начала работу или проверка завершилась. Если агент остановлен до
импорта, отчёт не появляется; обсуждение и повторный запуск можно продолжить
в чате. Состояние ожидания UI хранится в экземпляре панели; перезагрузка панели
сбрасывает его, а сохранённые отчёты остаются в истории.

### Зависимости

Первоначальный экспорт имеет неизвестное покрытие зависимостей. Агент может
задать selectors в `dependencies.yaml` и выполнить:

```powershell
node <plugin>/src/cli.mjs --root <project> --prepare-analysis <request-id> --dependencies <file>
```

Команда печатает путь нового неизменяемого `input-<hash>.yaml`, построенного из
тех же исходных снимков. Из этого файла нужно подготовить весь `result.yaml`.
`--dependencies-complete` допускается только после проверки полноты перечня,
включая подтверждённый пустой перечень. Старые экспорты сохраняются. Изменение
исходников между экспортами не подменяет факты. Импорт проверяется относительно
последней явно экспортированной области.

## Сборка и установка

Из корня репозитория:

```powershell
npm ci
npm run build:plugin
codex plugin marketplace add .
codex plugin add archiview@archiview-local
```

`dist/codex` содержит автономные Node-бандлы сервера и CLI, web UI, самодостаточный
MCP Apps SDK, спецификации и скилл. `node_modules` в кеше не требуется. Сборка
также создаёт `dist/panel.html` для запуска `src/server.mjs --panel` из исходников.
Перед запуском панели из исходников или протокольного стенда выполните сборку. Она
не регистрирует marketplace и не меняет конфигурацию Codex; установка выполняется
отдельной явной командой. После изменения исходников повторите сборку и установку.

Новый локальный чат подхватывает установленный плагин. Текущий чат может требовать
перезагрузки клиента для обнаружения новых инструментов и UI-точек входа.
Публичная публикация этой локальной поставки не выполняется.

## Проверка

`npm test` сначала собирает плагин. Тесты проверяют настоящий stdio MCP,
автономный пакет без node_modules и с запрещённым `net.Server.listen`, видимость
инструментов, пустые модельные поля UI-ответов, отсутствие fallback к fetch,
привязку к проекту, CLI-импорт, неизменность выбранного снимка, расширение
зависимостей, недопустимые пути и ссылки, идемпотентность и устаревание отчётов.
Отдельно сохраняются проверки обычного HTTP-приложения.

Для ручной проверки web UI и bridge предусмотрен:

```powershell
node scripts/preview-panel.mjs
node scripts/preview-panel.mjs --select-project
```

Он создаёт временный проект и явно обозначенный тестовый хост MCP Apps. В нём
внешние скрипты, стили и все сетевые запросы iframe запрещены CSP. Только внешний
тестовый хост пересылает вызовы в сервис; его HTTP-порт не является частью плагина.
Подключение UI к хосту отмечается отдельно. В стенде
можно отклонить поручение, повторить передачу и импортировать искусственный
результат с отметкой `test`. Стенд не запускает модель и не доказывает совместимость
с конкретным нативным клиентом Codex. Остановка процесса удаляет только его
временный проект.

На установленном Codex отдельно проверяются отображение дерева и деталей,
работа без loopback-запросов, отсутствие `archiview_ui_*` в каталоге модели
и фактический запуск агента после ui/message.
При отсутствии отправки сообщений интерфейс остаётся доступным для просмотра,
а кнопка анализа отключается с пояснением.
