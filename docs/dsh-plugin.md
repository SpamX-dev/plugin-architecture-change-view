# Плагин dsh

Каркас под плагин DeepSeek Harness. Он собирает существующие домены проекта в
две половины одного пакета и не переписывает ни прикладной сервис, ни интерфейс.

## Состав

| Домен проекта | Что делает плагин |
| --- | --- |
| `src/application` | не меняется: сессии, сравнения, снимки и проверки |
| `src/contracts/inventory.ts` | читается инструментами модели `archiview_inventory` и `archiview_context` |
| `src/archiview` | остаётся standalone-адаптером HTTP и CLI |
| `src/codex` | остаётся адаптером Codex (MCP Apps) |
| `web/archiview` | отдаётся маршрутами плагина и показывается во вкладке правой панели |
| `skills/module-boundaries` | публикуется в реестре скиллов dsh без копий |

Новые каталоги:

```text
src/dsh/
  host.ts        cordis-плагин: инструменты, маршруты, скилл
  sessions.ts    сессии прикладного сервиса по корню проекта
  tools.ts       описания и операции инструментов модели
  routes.ts      маршруты панели под префиксом
  skill.ts       разбор и публикация module-boundaries
  client/
    index.ts     регистрация типа вкладки и её тела
    body.ts      страница панели в iframe
scripts/build-dsh.ts
.archiview/modules/
  dsh-adapter.yaml       контракт хост-половины
  dsh-client-panel.yaml  контракт клиентской половины
```

## Сборка и установка

```powershell
npm run build:dsh
```

Сборка создаёт `dist/dsh/lib/index.js` (хост-половина, ESM для Node) и
`dist/dsh/lib/client.js` (браузерная половина в формате `window.__ModuleLoader__.load`).
Все результаты находятся в `dist/dsh/` — самостоятельном пакете для установки:
половины, интерфейс, скилл, документы, `cordis.patch.yml` и бандл CLI, на который ссылается поручение
анализа. Зависимостей у пакета нет, `@deepseek-ai/*` остаются внешними.

Установка — штатная для профиля:

```powershell
dsh plugin --profile <profile> add <путь к dist/dsh>
```

В Desktop-приложении то же делает Settings → Plugins (или инструмент
`plugin_manager` с `file:`-путём). Пакет объявляет `dsh.bundle` со своим
`cordis.patch.yml`, поэтому запись загрузчика появляется без ручной правки
профиля. Откат: удалить пакет тем же менеджером.

## Что уже работает

- Плагин активируется в профиле `desktop`: запись `include:archiview` —
  `active`, инструменты `archiview_inventory` и `archiview_context` доступны
  агенту, скилл `module-boundaries` появляется в каталоге скиллов.
- Инструменты модели читают инвентаризацию и контекст каталогов. При заданном
  `config.root` аргумент `projectRoot` может выбрать этот каталог или его подкаталог.
  Без настройки корнем служит `projectRoot` или рабочая папка чата агента.
  В общей рабочей папке `archiview_context` принимает путь к исходнику,
  например `{"path":"server/src/main.ts"}`, и возвращает контракты его репозитория.
- Маршрут `/archiview` отвечает редиректом, `/archiview/…` проходит политику
  соединения хоста: без cookie — 401, а не 404.
- Скилл `module-boundaries` публикуется из единственного файла пакета.
- Интерфейс получает базу API из метатега `archiview-base`, поэтому работает
  не только из корня сервера (правка `web/archiview/client.ts`).
- Префикс маршрутов доходит до вкладки через `webserver/index-inject`: строка
  `kind: "global"` присваивает `globalThis.__DSH_ARCHIVIEW__`, и клиент строит
  адрес iframe из него, а не из собственной константы.
- Обе половины проверяют префикс одной функцией `asPrefix`: принимается только
  локальный абсолютный путь. Сетевая ссылка `//host/path`, обратный слэш
  (`/\host/path` браузер разбирает так же), `?`, `#` и пробельные символы
  отклоняются: недопустимый `config.prefix` останавливает активацию, а
  испорченное внедрение откатывается к `/archiview`, поэтому адрес iframe
  остаётся на origin хоста.
- Вкладка ArchiView регистрируется в правой панели и показывает страницу.
- Корень проекта берётся из рабочего каталога чата: клиент передаёт
  `?session=<id>`, хост разрешает его через живую сессию, а для восстановленной
  вкладки — через сохранённый заголовок. Без параметра действует `config.root`.
- Кнопка анализа передаёт явное поручение в этот чат: страница присылает
  `archiview:send` с идентификатором чата открытой страницы. В версии 2 моста тело
  вкладки сверяет этот идентификатор со своим `sessionId` перед постановкой текста
  в очередь. При смене чата страница получает `archiview:send-failed`, при принятии
  поручения очередью выбранной сессии — `archiview:sent`.
  Просмотр и навигация сообщений не создают.

## Что осталось

1. **Команда открытия.** Тип вкладки зарегистрирован, но команды `/archiview` и
   горячей клавиши пока нет: нужен `ctx.commandUi` или шорткат панели.
2. **Проверка кнопки в живом GUI.** Передача проверена тестами отправителя;
   нажатие в браузере нужно подтвердить после перезагрузки страницы.
3. **Desktop.** В Web-профиле страница работает на same-origin. Electron грузит
   интерфейс по `file://`, поэтому тому же iframe нужен абсолютный адрес.

## Ограничения

- Плагин не запускает модель: просмотр только читает проект.
- Корень проекта никогда не берётся из URL запроса.
- Результаты сборки находятся в `dist/dsh/`; исходники остаются в `src/dsh`.
